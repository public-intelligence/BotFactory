# Bot Factory Data Inventory and Technical Safeguards

This document maps all personal, operational, and secret data handled by the **Bot Factory** software, where each item resides in the codebase, how it is protected, and its current retention behavior. It supports the [Privacy Policy](../PRIVACY.md) and DPGA Indicator 9a (Data Privacy and Security).

## 2. Technical Safeguards Verified in Code (`cddeee1`)

- **Multi-tenant isolation:** Global EF Core query filter on `OrganizationId` (`BotFactoryDbContext.cs`) isolates every organization's bots, knowledge base, conversations, telemetry, tools, and settings.
- **Encryption of secrets:** Provider API keys and tool credentials are encrypted with AES using `ENCRYPTION_MASTER_KEY` and masked in audit logs (`[AuditMask]`).
- **Fine-grained authorization:** Role- and permission-based endpoint authorization (`BotFactory.Core/Auth/Permissions.cs`). Public bot lookup (`GET /api/bots/by-slug/{slug}`) returns only `PublicBotResponse` (visual/greeting metadata), keeping prompts, retrieval settings, and organization details behind admin authentication.
- **Public access hardening:** Short-lived stateless anonymous tokens (15 min default), per-bot allowed-origin checks, and multi-layer rate limiting (per IP, per bot, and per organization).
- **Voice secret isolation:** ElevenLabs API keys travel in LiveKit agent dispatch metadata (`ctx.job.metadata`), visible only to the dispatched worker and never to room participants.
- **Fake-ID production guard:** `AUTH_USE_FAKE` defaults to `false` in deployment configs, and outside Development the API refuses to start with Fake-ID enabled unless `AUTH_ALLOW_INSECURE_FAKE=true` is explicitly set.
- **External tool safety:** JSON Schema argument validation (`ToolArgumentValidator`), network egress protection (`EgressGuard`), and automatic secret redaction (`ToolRedaction`).
- **CI secret scanning on deploy bundles:** `.github/workflows/deploy-bundle.yml` runs `scripts/build-deploy-zips.py --check` to ensure deployment bundles stay in sync and do not publish API keys, private keys, or support tokens.

## 3. Known Gaps and Planned Improvements

- **Automated data retention and deletion:** `CloseStaleConversationsJob` closes idle conversations but does not yet delete expired records. A configurable per-organization retention policy (defaulting to 90 days on CPI-operated instances) and automated purge/anonymization job are planned.
- **Administrative deletion on request:** A dedicated admin-panel workflow to delete or anonymize a specific conversation on data-subject request is planned (currently performed by authorized database administrators).
- **Expired session cleanup:** A periodic background sweep to remove abandoned expired rows from `Session` is planned.
- **Encryption at rest for database and object storage:** Disk/volume-level encryption for SQL Server and blob storage is a deployment-layer responsibility; operators should enable it per [`deploy/DEPLOYMENT.md`](../deploy/DEPLOYMENT.md).
- **Gemini API key transport:** Currently passed via query parameter in `GeminiChatService.cs`; migrating to the `x-goog-api-key` HTTP header is planned to eliminate any risk of key appearance in verbose HTTP client logs.
- **Historical secret remediation (completed in code):** Earlier audit findings (placeholder key format in `DbSeeder.cs`, hardcoded support key in `bot-factory-deploy.zip`, and development credentials in base `appsettings.json`) were remediated in PR #27 (`cddeee1`). Operators who used earlier bundles must rotate any previously exposed keys.
